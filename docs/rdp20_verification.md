## Implemented boundaries

- `DocumentCatalogController` resolves identity/membership and binds the Python GET contract. A route filter supplies private/no-store and Vary headers before binding or authentication, including errors. Safe 409/503 messages match Python exactly.
- `DocumentCatalogService` validates scope/cursors and delegates to a read-only repeatable-read JDBC snapshot. Metadata, readiness, revision and page query use one snapshot. Counts are Long within JavaScript's safe range; timestamps retain PostgreSQL microseconds; pagination uses null-last time/bytewise document ID keysets.
- The cursor and lock serialization match Python compact ASCII JSON. Tests use a token generated by the actual local Python codec and compare byte-identical Kotlin encoding. Model/workspace/limit/principal binding and the first-page 900-second expiry are retained. `DOCUMENT_LIST_CURSOR_SECRET` must be shared and at least 32 UTF-8 bytes; no secret values were copied from configuration.
- `SharedSchemaValidator` requires migration 006 and validates all four catalog relations/column types. Python alone owns DDL, backfill and certification. Listing can remain disabled while upgraded writers publish safely.
- Production `IngestionConfiguration` always supplies `JdbcDocumentPublicationRepository`. Older manually constructed offline fixtures retain their test seam; opt-in ingestion fixtures now explicitly supply the real publication repository. Catalog-wired ingestion resolves unchanged state per model, then rechecks readiness/hash under shared profile/document locks before replacing vectors. Counts, metadata, asset ownership and revisions share the vector transaction.
- New chunk writes use `doc_id`, source type/title and asset IDs. Replacement/counts support canonical and historical `document_id` keys, with canonical precedence and default chunking fallback. This does not rewrite historical aliases or certify old Kotlin rows.
- Asset identities follow current Python source-version/content-based JSON hashing. Immutable shared rows are inserted without overwriting another publication's image. New bytes use hash-only keys and Python's private directory layout; old Kotlin extension paths remain readable. Reference pruning is disabled before catalog certification. Physical garbage collection/backfill is not run.
- Directory cleanup considers only the selected model, root and recursive scan coverage. Database scan time and guarded deletion protect publications refreshed after a scan. Shared assets/sources survive while another publication references them.
- Corpus warming is an operator service overload, not a new HTTP route. It holds sorted Python profile session locks and pins source/target/cache adapters to one connection, preventing pool self-deadlock. Embeddings finish before each document transaction. Zero chunks, null source recency and existing asset ownership are preserved; provider failure leaves target status warming. Failed unlock attempts release every lock and abort the connection rather than return leaked session locks to a pool. The existing one-argument provider probe remains distinct.
